# 재정의: 입력, 출력, 제약조건

입력: 인자로 괄호들을 공백구분없이 그냥 받음

출력: 짝이 맞는 올바른 괄호 상태를 출력. 만약 짝이 맞지 않으면 최소갯수 괄호를 제거한것이 해답
만약 최소 갯수가 1개인데 1개를 제거해서 만들수 있는 괄호 조합이 100개면 100개를 줄바꿈으로 구분하여 출력

제약 조건: 출력의 순서는 상관없고, puts 사용가능

# 유추: 알고리즘, 자료구조

일단 정말 골치 아픈데, 무조건 올바른 세트는, 열린괄호에 달려있다. 
열린괄호가 없는왼쪽에 닫힌괄호? 전부 죽여야됨.
닫힌 괄호가 없는 오른쪽에 열린괄호? 전부 죽여야됨. 
그렇게 죽이고나서는 이제 하나씩 삭제해보며 상태가 만족할때까지 근데 그걸 어떻게 알수 있지?

예전에 풀어본적 있는데 괄호 만들기 이런 문제는 stack이 좋았던적이 기억나.
stack은 열린괄호면 일단 저장해두고 닫힌괄호면 pop해서 짝을 맞춰버릴수 있으니까. 
이걸로 상태 만족식을 만들어야되나?

근데 그럼에도 불구하고 상태만족식을 언제 호출하고 DFS 자체를 어떻게 설계할지 더 바깥쪽의 코드가 지금 계획이 안선다. 기존의 모든 백트래킹과 너무 다르게 느껴진다. 마치 백트래킹만을 물어보는 level2 인것 같다는 생각이 드는데도 백트래킹이라고 생각하고 바라봐도 요번에는 그게 적용 안될것만 같다.

# 재정의: 입력, 출력, 제약조건

입력: 인자로 괄호들을 공백구분없이 그냥 받음

출력: 짝이 맞는 올바른 괄호 상태를 출력. 제거는 글자를 없애는 게 아니라 공백(' ')으로 바꾸는 것. 짝이 맞지 않으면 최소 개수 괄호를 공백으로 바꾼 모든 조합을 줄바꿈으로 구분해 출력

제약 조건: 출력의 순서는 상관없고, 허용 함수는 puts, write만 가능(malloc 불가 -> 인자 문자열을 제자리에서 수정)

# 유추: 알고리즘, 자료구조

들어온 인자를 한 바퀴 돌면 지워야 할 2가지 개수(need_del_open, need_del_close)를 셀 수 있다. '('면 need_del_open을 +1, ')'면 need_del_open > 0일 때만 -1 하고 0이면 need_del_close를 +1 해야 "()"(0, 0)와 ")("(1, 1)의 순서 차이가 구별된다.

이렇게 세서 초기화를 완료한 상태로 재귀를 돈다.

매 칸마다 이미 적힌 글자를 ① 공백(' ')으로 지우는 갈래(해당 지울 개수가 0보다 클 때만 진입)와 ② 지우지 않고 그대로 남기는 갈래 두 가지를 돈다.

이때 재귀 인자로 '아직 닫히지 않고 남아있는 열린 괄호 개수(unclosed_open)'를 같이 들고 간다. 남기는 갈래에서 '('면 +1, ')'면 -1 하되, unclosed_open이 0인데 ')'를 남기려 하면 틀린 루트이므로 남기는 재귀를 아예 타지 않는다.

세 변수는 '지워야 할 남은 개수'와 '앞쪽 괄호 상태'만 뜻하므로 뒤쪽 미확인 글자 때문에 중간에 멈추면 안 된다. 반드시 문자열 끝까지 도달했을 때 세 변수(need_del_open, need_del_close, unclosed_open)가 모두 0, 0, 0이면 출력하고 재귀를 탈출한다.


# 계획: 모듈화

1. 초기화 (사전 1회 스캔)
   - 인자 문자열을 끝까지 한 번 훑어 need_del_open, need_del_close 구하기
   - 시작 위치 0번, unclosed_open = 0으로 재귀 진입

2. 재귀 (제자리 백트래킹)
   - 끝 조건: 문자열 끝에 도달했을 때 세 변수가 모두 0이면 puts로 출력하고, 아니면 조용히 return
   - 지우는 갈래: 현재 글자에 맞는 지울 개수(need_del_open 또는 need_del_close)가 0보다 크면, 원래 글자를 char 임시 변수에 빼둔 뒤 ' '으로 바꾸고 해당 개수 -1 해서 다음 칸 재귀 호출, 빠져나온 뒤 임시 변수로 원래 글자 복원
   - 남기는 갈래: 현재 글자가 '('면 unclosed_open + 1로 다음 칸 호출, ')'면 unclosed_open > 0일 때만 unclosed_open - 1로 다음 칸 호출 (0이면 호출 생략)
