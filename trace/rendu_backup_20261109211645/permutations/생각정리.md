# 1. 입력, 출력 및 제약 조건

- **입력:** 인자 1개로 주어지는 문자열.
- **출력:** 가능한 모든 순열을 **알파벳 오름차순(사전순)**으로 한 줄에 하나씩 표준 출력 (`puts`).
- **제약 조건 및 서브젝트 명세:**
  - 중복 문자는 주어지지 않음 (`sub.txt: We will not try your program with strings containing duplicates`). 즉, 모든 문자는 고유함.
  - 인자 개수가 2개가 아니면(`argc != 2`) 아무것도 출력하지 않고 종료 (`return 1` 또는 `0`).
  - 허용 함수: `puts`, `malloc`, `calloc`, `realloc`, `free`, `write`.

# 2. 외판원 문제(TSP)와의 핵심 차이 (왜 swap을 쓰면 안 되는가?)

- **TSP의 제자리 맞바꾸기 (`swap` 방식):**
  - 단순히 모든 순열($N!$)을 방문하기만 하면 되므로, 하나의 배열 안에서 앞뒤를 맞바꾸며 탐색해도 무방했음.
- **사전식 순열에서의 충돌:**
  - `swap(pos, i)`를 실행하는 순간, 뒤에 남아있는 글자들의 정렬 순서가 뒤집혀 파괴됨.
  - 예: `"abc"`에서 맨 앞자리에 `'c'`를 놓기 위해 0번과 2번을 바꾸면 `[ c , b , a ]`가 됨. 뒷자리에 `'b', 'a'`가 남아 다음 탐색 시 `cab`보다 `cba`가 먼저 출력되는 치명적 순서 역전 발생.
- **결론:**
  - 원본 정렬 배열은 절대 건드리지 않고 고정해 두어야 함.
  - 별도의 결과 버퍼에 **작은 알파벳부터 차례대로 빈칸을 채워 넣는 방식**이어야만 100% 사전순이 보장됨.

---

# 3. 핵심 자료구조 3요소

1. **`origin` (정렬된 원본 문자열):**
   - 입력받은 글자들을 알파벳 오름차순으로 정렬해 둔 고정 문자열.
   - 탐색 도중 절대 순서가 바뀌지 않음.
2. **`target` (결과 버퍼):**
   - 현재 탐색 중인 단어를 앞에서부터 한 글자씩 채워나가는 버퍼 (크기: `slen + 1`).
   - 마지막에 `\0` 종단 문자가 보장되어 기저 조건에서 `puts(target)`으로 한 번에 출력.
3. **`used` (사용 여부 체크표):**
   - `origin`의 각 글자가 현재 단어의 앞 칸에서 사용 중인지 기록하는 배열 (0: 미사용, 1: 사용 중).

# 4. 모듈화 전략 및 알고리즘 흐름

### [모듈 1: main 및 초기화]
1. `argc != 2` 예외 처리.
2. 알파벳 카운팅 배열(`table[26]`)을 이용하여 입력 문자열의 글자들을 오름차순으로 `origin`에 정렬 및 배치.
3. 글자 수(`cnt`)만큼 `used` 배열 할당(`calloc`) 및 `target` 버퍼 준비.
4. 백트래킹 시작: `recur_perm(origin, used, target, cnt, 0)`.
5. 메모리 해제 및 정상 종료.

### [모듈 2: recur_perm (사전순 백트래킹)]
- **매개변수:** `origin`, `used`, `target`, `slen`, `pos` (현재 채울 빈칸 인덱스)
- **기저 조건 (Base Case):**
  - `pos == slen`에 도달하면 모든 칸이 완성된 것이므로 `puts(target)` 출력 후 반환(`return`).
- **재귀 상태 전이 (단일 루프):**
  - 루프 변수 `j`를 `0`부터 `slen - 1`까지 1씩 증가시키는 **단 하나의 반복문** 실행.
  - `if (used[j] == 0)` (아직 안 쓴 글자라면):
    1. `used[j] = 1;` (사용 중 표시)
    2. `target[pos] = origin[j];` (현재 칸에 글자 채우기)
    3. `recur_perm(origin, used, target, slen, pos + 1);` (다음 칸 채우러 재귀 호출)
    4. `used[j] = 0;` (호출 복귀 후 다시 미사용으로 원상복구)

# 5. 복잡도 및 결론

- **시간 복잡도:** $O(N \cdot N!)$
  - 26개의 모든 알파벳이 다 들어오더라도 중복 순열을 배제할 수 없는 본질적인 전수 탐색 문제.
  - DP 최적화 대상이 아니며, 사전순으로 $N!$개를 빠짐없이 생성하여 출력하는 순수 DFS 백트래킹이 유일한 해법.
- **공간 복잡도:** $O(N)$
  - 재귀 호출 스택 깊이 최대 $N$, 버퍼 및 테이블 메모리 최대 27바이트 수준으로 극도로 가볍고 안전함.
